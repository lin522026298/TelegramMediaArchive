# Telegram 群媒体归档器帮助文档

本程序用于把 Telegram 群组或频道里的图片、视频下载到本地。它的重点是可断点续传、可校验、可长期运行，而不是替代 Telegram Desktop 的聊天功能。

## 你需要先知道的事

- 下载目录默认是当前用户的 `Downloads\TelegramMediaArchive`；已安装用户仍使用原有设置。空闲时可以在首页修改。
- `state` 目录保存登录会话、配置和数据库，里面有敏感信息，不要发给别人，也不要提交到 GitHub。
- `media` 目录保存真正下载下来的图片和视频。
- `logs` 目录保存日志。
- 下载走 Telegram API，可以关闭 Telegram Desktop。
- 如果电脑关机、网络断开或程序停止，下次点 `继续未完成` 可以从 `.part` 文件继续。
- 程序会预留至少 20 GiB 磁盘空余空间，空间不够时会自动等待，不会继续把磁盘写满。

## 第一次使用

1. 打开程序。
2. 在 `归档目录` 里选择一个容量足够的磁盘目录。
3. 如果是源码运行，先点 `安装/更新依赖`。
4. 登录 Telegram：
   - 优先尝试 `内置 API 登录`，输入带国家区号的手机号。
   - 如果你已经有 `api_id/api_hash`，也可以用 `API 登录`。
   - 登录会打开一个终端窗口，验证码和二步验证密码都在终端里输入。
5. 点 `选择群组`，在终端里选择要归档的群组或频道。
6. 点 `索引媒体`，程序会先把图片和视频消息写入本地数据库。
7. 点 `月份统计` 看数量和大致体积。
8. 点 `继续未完成` 开始下载全部未完成项目，或用 `按范围下载` 只下载某个日期范围。

## 界面区域说明

新版界面采用左侧导航：

- `总览`：归档目录、本地状态、常用操作。
- `下载`：日期范围、类型、数量限制、并发数，以及下载/继续/校验。
- `账户`：登录、内置 API 登录、选择群组、列出会话、索引媒体。
- `设置`：语言、暗色模式、下载守护、轮询、每日 SQLite 快照、开机自启动和关闭窗口行为。
- `帮助`：帮助文档、技术文档、关于、复制命令、打开日志。

界面已启用 Windows 高 DPI 感知，4K 屏幕下应比旧版更清晰。如果 Windows 缩放比例改变后仍觉得模糊，关闭并重新打开 APP。

### 总览

- `选择`：选择保存目录。
- `打开根目录`：打开当前归档根目录。
- `刷新`：重新读取本地状态。
- `继续未完成`：继续所有 pending/error/downloading 记录。
- `月份统计`：估算每个月数量和大小。
- `校验文件`：检查已完成文件是否存在、大小是否匹配。
- `打开下载目录`、`打开状态目录`、`打开日志目录`：打开对应文件夹。

### 账户

- `API 登录`：使用你自己的 `api_id/api_hash` 登录。
- `内置 API 登录`：使用内置 Telegram Desktop API 模板登录，适合 `my.telegram.org/apps` 创建应用报错的账号。
- `选择群组`：选择要下载的群组或频道。
- `列出会话`：列出最近会话，用于确认群组名称。
- `索引媒体`：只索引图片和视频，不下载文件。
- `设置帮助`：在日志区显示 CLI 的设置说明。

### 下载

- `手机号`：登录时使用，必须带国家区号，例如 `+1...`。
- `起始日` / `结束日`：格式为 `YYYY-MM-DD`。留空表示不限制。
- `类型`：`all` 下载图片和视频，`photo` 只下载图片，`video` 只下载视频。
- `数量限制`：只处理前 N 个项目，适合测试。正式下载可留空。
- `并发数`：同时下载几个文件。默认 4，允许 1-8。网络慢或影响其他业务时调低到 1-2。
- `按范围下载`：按上面的日期、类型、限制开始下载。
- `继续未完成`：忽略日期范围，继续整个归档目录中未完成的记录。
- 如果在 `设置` 里打开了“完成一轮后继续轮询已索引待下载项”，下载命令会在一轮结束后重新检查本地数据库，而不是直接退出。

### 设置

- `语言`：在中文和 English 之间切换。
- `暗色模式`：切换明色/暗色主题。
- `下载异常退出后自动重启`：只对从 APP 里启动的下载命令生效。如果下载进程异常退出，APP 会等待 10 秒后用上一条下载命令重新启动。你手动点 `停止当前命令` 时不会自动重启。
- `完成一轮后继续轮询已索引待下载项`：让下载命令持续运行，并按设定间隔重新查询本地 SQLite 中尚未完成的记录。
- `轮询间隔（秒）`：每轮结束后等待多久再查一次，最少 10 秒，默认 300 秒。
- `自动索引群组后续新发的图片和视频`：定时访问已选择的群组，只加入本地数据库最高消息号之后的新图片/视频。开启它会自动保持下载进程运行。
- `群组新媒体检查间隔（秒）`：默认 300 秒，最少 10 秒。它与本地待下载轮询互相独立，但二者使用同一个 Telegram 登录会话。
- `关闭窗口时后台保留`：打开后，点窗口右上角关闭按钮会隐藏窗口，APP 仍可通过系统托盘显示；下载进程不会因此中断。
- `开机自启动`：在 Windows 启动文件夹创建启动脚本，下次开机自动打开 APP，并使用当前归档目录。
- `应用运行期间每天创建一份 SQLite 一致性快照`：APP 打开时每 5 分钟检查日期，当天尚无快照就调用 SQLite 正规备份接口。下载可以继续写库。
- `快照镜像目录`：可选的第二份快照位置。留空时只写 `state\snapshots`；当前机器可设为 `D:\Cloud Storage\Openlist\state-backups`。
- `立即备份`：忽略“今天已经备份”的判断，重新生成并原子替换当天快照。
- `归档目录`：位于“总览”页，保存登录、断点、媒体和日志。换目录前请确认你真的要切换任务。

### 日志和工具

- `打开状态目录`：打开配置、会话和数据库目录。
- `打开日志目录`：打开日志目录。
- `复制上一条命令`：复制最近一次执行的命令，方便排查问题。
- `清空日志`：只清空界面日志，不删除文件。
- 界面最多显示最近 5,000 行。APP 启动的命令会另外保存到 `logs\telegram-download.log`，包含时间、输出和退出原因；单份最多 10 MiB，另外保留 3 份旧日志。
- `停止当前命令`：先写入安全停止标记，下载器会检查并取消正在等待的网络请求，刷新 `.part` 和数据库再退出；30 秒仍无响应才终止进程。下次启动会按磁盘上的 `.part` 继续。

## 功能对应关系核对

- 登录相关按钮只在 `账户` 页。
- 下载参数只在 `下载` 页。
- 目录和状态查看在 `总览` 页。
- 语言、主题、下载守护、轮询、自启动、关闭行为只在 `设置` 页。
- 文档和排查工具在 `帮助` 页。

## 断点续传如何工作

每个未完成文件会先写成 `.part` 文件。下载完成后才改名为正式文件。下次继续时，程序按磁盘上 `.part` 文件的真实大小恢复，不依赖界面进度文字。

并发下载时，每个文件有自己的 `.part`，不会多个任务写同一个文件。程序按消息时间和消息 ID 分批调度，例如并发 4 就同时处理当前顺序里的 4 个文件，等这一批结束后进入下一批。

## 每日数据库快照如何工作

快照主目录是 `<归档目录>\state\snapshots`，文件名是
`archive-YYYY-MM-DD.sqlite3`。程序先写临时数据库，执行 `PRAGMA quick_check`，
通过后再原子替换正式快照；镜像副本也执行相同检查。

这不是 Windows 计划任务：只有 APP 处于运行状态（包括隐藏到托盘）时才会检查。
完全退出 APP 后不会在后台启动下载器或备份程序。重新打开时若当天没有快照，会自动补当天一份。

## 一键连续加密云归档

已部署 OpenList 侧车的机器可以双击 `D:\Cloud Storage\Openlist\启动连续归档.cmd`。它按顺序启动 OpenList、加密上传器和 Telegram APP，然后自动完成：

```text
群组增量索引 -> 断点下载到本地完整文件 -> 内容和文件名加密 -> 上传百度网盘 -> 云端校验 -> 删除该份本地明文
```

单个文件下载完成前仍只存在本地 `.part`，不会上传半成品。云端验证失败时本地正式文件不会删除。暂停或关机前双击 `停止连续归档.cmd`；它先安全停止 Telegram 下载，再停止上传器和 OpenList。两个入口都不会创建开机项、计划任务或 Windows 服务。

如果只想迁移本地已有正式文件，不跟进 Telegram，继续使用 `启动加密上传.cmd`。加密恢复材料在 OpenList 工具目录的 `credentials` 中；丢失密码或盐将无法解密云端文件。

## 常见问题

### 当前版本的使用限制

在进一步加固前，一个归档目录只用于一个群组，并且只运行一个归档器实例。
下载时不要修改归档目录或再次登录/选群。完整退出前先停止当前命令；恢复文件建议
使用空目录，避免同名旧文件被跳过。此轮整体审查的未解决项见技术文档中的审查报告。

### 可以关闭 Telegram Desktop 吗？

可以。下载使用 Telegram API，不依赖 Telegram Desktop 保持打开。

### 可以关闭这个归档器 APP 吗？

如果下载是从 APP 里启动的，建议先点 `停止当前命令`，确认停止后再关闭 APP。下次打开后点 `继续未完成`。电脑重启后也一样可以继续。

如果打开了 `关闭窗口时后台保留`，点右上角关闭按钮只是隐藏窗口，APP 启动的下载命令会继续运行。完全退出 APP 或重启电脑后，重新打开 APP，再点 `继续未完成` 即可接上 `.part` 文件。

### 为什么窗口还开着但不下载？

APP 窗口和下载子进程是两回事。旧版本下载进程如果异常退出，窗口仍可能开着但没有传输。新版可打开 `下载异常退出后自动重启`，让 APP 在下载进程失败时自动拉起；也可以打开 `完成一轮后继续轮询已索引待下载项`，避免一轮结束后直接退出。

0.1.6 还修复了两种停滞：连续模式触及磁盘保护线后会等待而不是退出，空间释放后
自动继续；单次连接、消息读取或网络分块连续 3 分钟没有返回时，会保留断点并
重建连接，10 秒后继续后续批次；失败文件仍保留在数据库和磁盘，下一轮重试，
不会让一个持续失效的文件堵住整个队列。视频可以下载几个小时，这个 3 分钟不是视频总时长限制。
没有待下载记录、等待磁盘/上传队列、轮询间隔内安静，都是正常等待，不会被当作卡死。

若整个 APP 或电脑上的所有相关进程被关闭，内部守护无法自救，仍需要手动运行
`启动连续归档.cmd`。没有开启自动启动时，完全退出程序后不会自动复活。

一键启动现在也会校验 OpenList 的残留 PID：不存在的进程或已被别的程序复用的
PID 只清理标记，不结束其他进程；真实 OpenList 进程存在但未监听时会报错，避免重复启动。

### 为什么速度不高？

速度通常受 Telegram、账号、网络和目标数据中心限制。提高并发可以改善总吞吐，但并发太高可能影响其它业务，也可能触发 Telegram 限速。建议从 4 开始，不稳定时降到 2。

### 空间不够怎么办？

先看 `月份统计` 的总大小，再确认磁盘空余空间。程序默认预留 20 GiB，下一批完成后可能低于该值时会等待。你可以换更大的归档目录，或分日期范围下载。

### 旧的 Telegram Desktop 导出可以删吗？

确认本程序已经登录、选群、索引、下载样本并通过 `校验文件` 后，旧导出目录通常可以删除。但不要删除本程序的归档目录，尤其不要删除 `state` 和还在下载中的 `.part`。

### GitHub 分享要注意什么？

只分享源码、文档和打包产物。不要分享 `state`、`media`、`logs`、`.session`、`archive.sqlite3`、个人手机号、验证码、API hash 或任何下载内容。

## 0.1.7 安全规则与云恢复

- 一个下载目录绑定一个群，首次选群或旧任务首次运行时自动记录绑定，不改已有文件名和断点。换群请选新目录；误选会拒绝执行，不会拿新群下载旧群的记录。
- 一个目录只能有一个 Telegram 会话命令。第二个窗口可以查看状态，但重复登录、选群、索引或下载会报“已有会话运行”。先停止原任务，不要删除锁文件来强行启动。
- 登录/选群终端也属于正在运行的命令。执行期间下载目录不可改；即使外部更改设置，停止仍针对启动时目录。
- 勾选后台保留时，关闭窗口只是隐藏到托盘。真正退出会先停止所启动的下载，等待子进程、日志和备份收尾，再退出；30 秒不能正常停止时只结束该命令的进程树。没有托盘时不会把窗口隐藏成无法找回的状态。
- 云中转工具是独立进程。设置页选择已经完成配置的工具目录后，首页显示近期心跳、待上传大小和每日备份状态，每 10 秒更新。心跳超过 120 秒未更新或已停止会告警；近期心跳不等于所有文件已上传。`启动 / 恢复上传` 不重新申请授权、不建开机项，只启动已配置上传流程。
- 可以关闭 Telegram Desktop、浏览器、登录完毕的终端和启动提示窗口。不要结束仍在工作的下载器/上传器/rclone/OpenList；关闭 GUI 的影响取决于“后台保留”。真正退出 GUI 只停止它拥有的 Telegram 命令，不停止独立上传器。
- 每日备份在运行期间自动检查。镜像不可写会记为 `error` 并约 5 分钟后重试，上传继续；请修复磁盘/目录问题，备份错误不能长期忽略。
- 本地明文只有在删除安全门通过、重新云端验证、大小/哈希不变后才删除。云端暂时不可访问时保留本地并重试，不会因为昨天验证过就直接删。
- 使用中转目录里的 `scripts\恢复文件.ps1`，给出 `archive/media/...` 的逻辑远端路径及一个空的目标目录。需保留 `manifests\upload-manifest.jsonl` 与加密凭证。恢复依次核对文件集合、大小、SHA-256 和 cryptcheck，全部通过才提示成功；非空目标直接拒绝，失败结果留在本地供检查。
- 备份归档 `state`、中转 `credentials/config/manifests`。云盘里的密文不能替代密码或本地任务数据库。不要将这些私人目录、真实媒体名称、日志、授权码打包分享。
