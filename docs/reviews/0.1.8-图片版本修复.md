# 0.1.8 图片下载版本一致性

## 证据与结论

本机锁定 Telethon 1.43.2 的 `custom/file.py` 对 Photo 计算最大字节数，`utils._get_file_info` 默认选最后一个尺寸。原项目索引使用前者，`iter_download(message.media)` 使用后者。两种 JPEG 大小不同时，完整的另一个 JPEG 也会被严格长度检查拒绝。这是版本选择错误，不是应该删除大小校验的理由；也不能解释所有服务器超时。

## 修复路径

统一 `select_photo_variant`；原生图片下载使用显式 InputPhotoFileLocation 和对应 DC/大小。progressive 用 max(sizes)，无网络版本时处理缓存 JPEG。完整文件仍必须达到所选大小才原子改名入队。

为断点建立持久来源身份。没有旧身份或身份变化时，把 pending 图片旧 final/part 保存到 `state/photo-quarantine`，记录 provenance，再开始新版本下载。同版本重启继续，不重置视频，不自动删除隔离副本。表为兼容性新增，不重写旧媒体主键、文件路径、已归档状态和云端数据。

## 验收与边界

新增测试覆盖列表乱序、progressive 分层乱序、索引一致、非法版本拒绝、缓存大小、旧断点/旧完整文件隔离、跨数据库重开身份持久性、身份变化重新隔离、显式位置/DC/大小/续传偏移、短文件仍失败。完整测试包含原视频续传、会话互斥、加密恢复和 UI 回归。

真实部署检查单独记录在本机中文操作记录：安全停止、SQLite backup API 快照、保留旧程序、真实消息元数据对照、少量历史失败图片下载及云校验、视频断点前缀与增长、数据库健康和上传心跳。公开包不得包含真实媒体名、群组 ID、会话、密钥或运行库。发布新提交，不改旧 GitHub 历史。
