## 2026-07-31：完整部署

状态：部署完成，正式后台迁移已启动。

### 基础组件

- 安装 OpenList v4.2.4 Windows amd64并核对官方包 SHA-256。
- 安装 rclone v1.74.4 Windows amd64并核对官方包 SHA-256。
- OpenList 只监听 `127.0.0.1:5244`。
- OpenList upload/transfer worker 均设为 1；未创建服务、启动项或计划任务。
- 使用用户自己的百度开放平台应用完成 OOB OAuth 授权。
- 创建 OpenList 百度存储 `/baidu-encrypted-archive`，驱动根为
  `/apps/Encrypted Archive/加密上传用`。
- 根目录原有 `/加密上传用` 可列出但不可进入（百度 errno -7），未用作正式目标。
- WebDAV 改用 OpenList 永久 Bearer Token，绕开 rclone Basic Auth 401。

### 加密链路

- 配置 `crypt -> chunker(256Mi) -> WebDAV -> OpenList -> 百度网盘`。
- 启用文件内容、文件名和目录名加密。
- 恢复密码、盐、OpenList 令牌和百度凭证仅保存在 D 盘明文凭证目录，不进入 Git。
- 修复 Windows PowerShell 5.1 POST 中文 JSON 被静默写成问号的问题；OpenList API
  统一使用 UTF-8 body bytes 与 charset。

### 真实试点

- 生成 1 MiB 与 270 MiB 随机样本，后者跨越 256 MiB 分块边界。
- 上传完成：2 个逻辑文件对应 5 个底层对象。
- `rclone cryptcheck`：0 差异，2 个匹配文件。
- 整份回下载后逐文件 SHA-256 与源文件一致。
- 底层物理名称中不含试点目录名或两个原文件名。
- 对两个文件逐一执行上传器使用的精确 `cryptcheck` 调用，均通过。
- 对已存在的小样本执行 `--immutable` 重试，安全跳过且退出码为 0。
- 生成绑定当前 rclone 配置哈希的 `manifests\pilot-verification.json`。

### 应用与数据一致性

- Telegram App 更新为 0.1.3，加入高 DPI、Windows 11 风格分区、中英文、暗色模式、
  每日一致性快照、后台关闭、异常守护和待下载轮询设置。
- 每日快照使用 SQLite `backup()`、`quick_check` 和原子替换；主副本在 E，镜像在 D。
- 云上传器运行期间也每 5 分钟检查每日快照，Telegram App 关闭时仍会备份。
- 新增 `archived` 状态，下载器不会把已云归档并清理的文件重新下载。
- 新增 `cloud-backpressure.pause`，100/50 GiB 迟滞与 150 GiB 最低空闲保护。

### 上传器安全模型

- 上传状态持久化于 `manifests\upload_state.sqlite3`。
- 上传并发 1，按日期、消息 ID、媒体序号调度。
- `remote_verified` 与 `local_purged` 分成两个阶段。
- 删除前重新 SHA-256；先把 Telegram DB 标记为 `archived`，再仅 unlink 单个文件。
- 清理失败保持 `remote_verified`，不会退回上传状态。
- 进程中断后恢复 hashing/uploading/verifying，保留已验证状态。
- 停止使用哨兵和单实例文件锁，不依赖控制台文本判断状态。
