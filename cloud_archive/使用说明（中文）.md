# Telegram 加密云归档使用说明

最后更新：2026-08-07

这套工具把 Telegram 已下载完成的图片和视频加密后上传到百度网盘。文件内容、
文件名和目录名都会在本机加密；百度网盘只保存密文和加密名称。

## 一分钟开始

需要一边跟进 Telegram 群更新、一边加密上传时：

1. 双击 `launchers\启动连续归档.cmd`。
2. APP 会打开并自动继续全部断点，同时每 300 秒增量索引群组新图片/视频。
3. 上传器每 60 秒接收已经下载完成的正式文件，加密、上传、校验并安全清理。
4. 暂停或关机前双击 `launchers\停止连续归档.cmd`，等待整条链路安全停止。
5. 电脑重启后不会自动运行；需要继续时再次手动双击启动入口。

只想上传本地已有正式文件、不启动 Telegram 下载时：

1. 双击 `启动加密上传.cmd`。
2. 看到“已在后台运行”后可以关闭命令行窗口。
3. 双击 `查看加密上传状态.cmd` 可随时查看当前文件、队列和错误。
4. 要关机或暂停时，先双击 `停止加密上传.cmd`，等待“已安全停止”。
5. 重启电脑后不会自动运行；需要继续时再次双击 `启动加密上传.cmd`。

`启动加密上传.cmd` 不启动 Telegram 下载器。`启动连续归档.cmd` 则按
OpenList -> 上传器 -> Telegram APP 的顺序启动整条链路。两者都不创建 Windows
服务、计划任务或开机启动项。

下载和上传均未设置本地带宽上限。Telegram、百度网盘、运营商和网络状况仍可能决定
实际速度。下载并发 3、上传并发 1 是任务并发与完整性策略，不是 MiB/s 限速；不要为
追求瞬时速度直接修改并发或分块参数。

## 三个程序各自做什么

- `TelegramMediaArchive.exe`：登录 Telegram、索引群组、下载、维护 `.part` 断点。
- `openlist.exe`：只在本机 `127.0.0.1:5244` 提供百度网盘 WebDAV。
- `TelegramCloudUploader.exe`：读取已完成队列，调用 rclone 加密、上传、校验和清理。

`rclone.exe` 是上传器调用的底层工具。它先加密，再切成 256 MiB 分块，最后通过
OpenList 上传。三个程序相互解耦；网络失败不会破坏 Telegram 的登录或下载断点。

## 可以关闭哪些窗口

- 启动脚本弹出的命令行窗口：可以关闭，上传器已在后台运行。
- Codex、Chrome 和百度网盘桌面客户端：可以关闭，本工具不依赖它们。
- Telegram 桌面客户端：可以关闭，本工具不依赖它。
- `TelegramMediaArchive.exe`：可以最小化；点窗口右上角关闭会按当前设置隐藏到托盘。
  连续归档期间不要从托盘“退出”或在任务管理器中结束它。
- OpenList：上传器运行时不能关闭。
- `TelegramCloudUploader.exe`：不要在任务管理器里直接结束，使用停止脚本。
- `TelegramMediaArchiveCLI.exe`：不要强制结束，使用 `停止连续归档.cmd` 安全停止。
- E 盘归档目录和 D 盘 OpenList 工具目录：运行期间不能断开、改名、移动或删除。

如果 OpenList 或网络意外中断，源文件不会删除。恢复网络后重新启动即可重试。
需要关机或完全退出时，先运行 `停止连续归档.cmd`；它确认安全停止后，上述程序都可关闭。

## 文件经过的完整流程

```text
Telegram .part
  -> 下载完成并原子改名为正式文件
  -> 本地 SHA-256
  -> 内容、文件名、目录名加密
  -> 256 MiB 分块上传
  -> rclone cryptcheck
  -> 再次核对本地 SHA-256
  -> SQLite 记录改为 archived
  -> 永久删除这一份本地正式文件
```

上传器只读取 SQLite 中 `status='downloaded'` 的正式文件，不读取 `.part`。单个文件
必须先完整下载，不能在同一文件尚未完成时边写边传。这样断网或重启后可以可靠重试。

## 为什么允许删除本地文件

自动清理受四重保护：

1. 已用 1 MiB 和 270 MiB 随机样本完成真实百度网盘试传。
2. 270 MiB 样本跨越了 256 MiB 分块边界。
3. `cryptcheck` 报告 0 差异，回下载后 SHA-256 与源文件完全一致。
4. 已确认百度底层看不到样本原目录名和原文件名。

结果保存在 `manifests\pilot-verification.json`。该文件还绑定当前
`config\rclone.conf` 的 SHA-256；加密配置被修改后，自动删除会立即锁死，必须重新做
试点。上传器不会递归删除目录，只会删除刚刚重新校验过的那一个正式文件。

## 顺序和断点

- 首次队列按 Telegram 消息日期、消息 ID、媒体序号排列。
- 上传并发固定为 1，不改变队列次序。
- 队列保存在 `manifests\upload_state.sqlite3`，不是保存在控制台文字里。
- 进程或电脑重启后，会恢复未完成状态并重试同一逻辑路径。
- `--immutable` 防止无意覆盖已有云端对象；同内容重试会安全跳过。
- 分块器先写临时名称，完成后再服务端改名，避免把半成品当成完整文件。

## 磁盘空间保护

上传器会创建：

`E:\电报视频导出_断点续传\state\cloud-backpressure.pause`

有这个文件时，新版 Telegram 下载器不会领取下一批任务。默认规则：

- 待云端清理的完整文件超过 100 GiB：暂停新下载。
- E 盘空闲低于 150 GiB：暂停新下载。
- 只有待清理量低于 50 GiB且空闲不少于 150 GiB时，才自动解除暂停。

存量缓存已完成迁移后，可以使用连续归档模式。下载器遇到反压标记会等待，上传器会
边上传、边验证、边释放 E 盘，不需要等所有文件先复制到 D 盘。

## 常用入口

- `启动连续归档.cmd`：手动启动 OpenList、上传器和 Telegram 增量归档。
- `停止连续归档.cmd`：先安全停止 Telegram 下载，再停止上传器和 OpenList。
- `启动加密上传.cmd`：启动 OpenList 和后台上传器。
- `停止加密上传.cmd`：请求上传器在安全位置停止。
- `查看加密上传状态.cmd`：显示阶段、心跳、当前文件、计数和最近错误。
- `打开云归档日志.cmd`：打开 `logs` 目录。
- `打开 OpenList 管理页.cmd`：打开本机管理页。
- `停止 OpenList.cmd`：仅在上传器已经停止后使用。

## 每日 SQLite 一致性快照

Telegram App 或加密上传器只要有一个在运行，就会每 5 分钟检查一次：

- 主快照：`E:\电报视频导出_断点续传\state\snapshots`
- 镜像快照：`D:\Cloud Storage\Openlist\state-backups`
- 文件名：`archive-YYYY-MM-DD.sqlite3`

它使用 SQLite 正规 `backup()` 接口，随后执行 `PRAGMA quick_check`，不是复制正在变化
的 WAL 文件。当天快照已存在时不会反复覆盖；手动“立即备份”才会刷新。

## 云端实际位置

OpenList 挂载名是：

`/baidu-encrypted-archive`

百度网盘应用目录中的实际根是：

`/apps/Encrypted Archive/加密上传用`

其中会出现固定技术容器 `TelegramMediaArchiveEncrypted-v1`。容器下面的原目录名、
文件名和内容均已加密，百度网页不能直接预览，这是正常现象。不要在百度网页中改名、
移动或编辑这些密文和分块。

## 恢复文件

先启动 OpenList，再运行：

```powershell
& "D:\Cloud Storage\Openlist\scripts\恢复文件.ps1" `
  -RemotePath "archive/media/2023/2023-09-01/某文件.mp4" `
  -DestinationDirectory "D:\恢复输出"
```

`RemotePath` 是解密后的逻辑路径。也可用 rclone 查看：

```powershell
& "D:\Cloud Storage\Openlist\rclone\rclone.exe" `
  --config "D:\Cloud Storage\Openlist\config\rclone.conf" `
  lsf "baidu_crypt:archive/media" --recursive
```

必须通过 `baidu_crypt:` 恢复，不能直接下载百度网页里看到的分块后当视频打开。

## 凭证和不可丢失的数据

明文恢复凭证：

`D:\Cloud Storage\Openlist\credentials\恢复凭证（明文）.txt`

百度开发者凭证和 OAuth 令牌也在同一 `credentials` 目录。按当前需求，它们不防本机
用户，只用于确保本人可以恢复；绝不能提交 GitHub，也不要上传到百度网盘。

最重要的是 `RCLONE_CRYPT_PASSWORD` 和 `RCLONE_CRYPT_SALT`。二者丢失后，云端密文
无法恢复原名和原内容。建议把整个 `credentials` 目录另存一份到可信的离线位置。

## 遇到问题

- 状态一直不动：打开 `logs\cloud-uploader.log`，确认 OpenList 正在运行。
- 显示 `remote_verified`：云端已验证，上传器正在等待或重试本地安全清理。
- 显示 `error`：源文件仍保留，上传器会按 1 分钟到 1 小时退避重试。
- 文件名含全角问号等字符也受支持；上传器已关闭 rclone 对 Windows 本地名称的二次解释。
- 授权过期：OpenList 通常会用 refresh token 自动刷新；若失败，重新授权后再启动。
- 停止脚本等待较久：它正在结束 rclone 子进程或文件校验，不会强制杀进程。
- 配置修改后拒绝删除：这是安全门生效，需要重新跑完整试点，不能手改 JSON 绕过。

## 禁止事项

- 不要删除 `.part`、实时 `archive.sqlite3` 或 Telegram `.session`。
- 不要把实时 SQLite 放在 WebDAV 上运行。
- 不要同时启动两个上传器。
- 不要在任务管理器里强制结束正在清理本地文件的进程。
- 不要编辑 `rclone.conf` 的 crypt 密码或盐后继续自动删除。
- 不要把 `credentials`、实际 `rclone.conf`、令牌或用户数据库提交 GitHub。
